# EDITORIAL SOURCE PERFORMANCE & VALUE ENGINE

## 1. Purpose

The Editorial Source Performance & Value Engine (ESPVE) evaluates how effectively an integrated source performs its assigned editorial functions in real operation.

It does not rank sources by prestige and does not attempt to create a universal reliability score.

The question is:

> Is this source actually delivering the editorial capability for which MALDITOESPEJO maintains it, and what is the evidentiary value of that contribution?

## 2. Core principle

`SOURCE VALUE = FITNESS FOR FUNCTION + EVIDENTIARY CONTRIBUTION + OPERATIONAL PERFORMANCE + INDEPENDENCE CONTRIBUTION`

A source may be highly authoritative but have low operational value for a particular function. Conversely, a specialist source may be extremely valuable for one narrow fact class.

## 3. Performance dimensions

### 3.1 Detection performance
Measures whether the source identifies relevant developments within the required time window.

Indicators:

- detection timeliness;
- event coverage;
- missed relevant events;
- duplicate/noise rate;
- alert usefulness.

### 3.2 Verification contribution
Measures whether the source materially assists verification.

Indicators:

- primary evidence contribution;
- directness;
- corroboration contribution;
- contradiction detection;
- evidentiary specificity.

### 3.3 Independence contribution
Measures whether the source adds a genuinely distinct evidentiary lineage.

### 3.4 Coverage contribution
Measures whether the source closes or reduces a documented coverage gap.

### 3.5 Temporal performance
Measures publication/update timeliness relative to the editorial requirement.

### 3.6 Provenance performance
Measures whether source material remains traceable, attributable, versioned, and auditable.

### 3.7 Operational performance
Measures availability, endpoint stability, feed continuity, schema stability, and reproducibility.

### 3.8 Revision performance
Measures the frequency and materiality of corrections/revisions and whether they are transparently documented.

### 3.9 Noise burden
Measures irrelevant, duplicated, low-value, or misleading signals generated for the newsroom's assigned function.

Noise is not inherently bad; high-volume sources may be useful when the editorial function requires broad detection.

## 4. Value states

- `HIGH_VALUE`
- `VALUABLE`
- `FUNCTIONAL`
- `LIMITED_VALUE`
- `REVIEW_REQUIRED`
- `UNASSESSED`

`UNASSESSED` is not equivalent to low value.

## 5. Performance is function-specific

Every assessment must identify:

- source;
- function;
- topic;
- geography;
- evidence class;
- time period;
- expected capability.

A source should never receive a universal performance judgment detached from its function.

## 6. Performance evidence

Assessment should use observable records such as:

- signals generated;
- relevant events detected;
- verification records;
- evidence packs;
- source revisions;
- correction notices;
- endpoint incidents;
- missed releases;
- false/duplicate alerts;
- cases where the source materially contributed to a decision.

Anecdotal impressions should not be treated as equivalent to operational evidence.

## 7. Contribution categories

### `DETECTION_ONLY`
Useful primarily for discovering developments.

### `VERIFICATION_SUPPORT`
Materially assists verification but does not independently establish the proposition.

### `PRIMARY_EVIDENCE`
Provides authoritative or direct evidence for the relevant fact class.

### `INDEPENDENT_CORROBORATION`
Adds a genuinely independent evidentiary lineage.

### `CONTEXT`
Improves interpretation without materially establishing the core fact.

### `NOISE`
Produces signals with insufficient editorial value for the assigned function.

A single source may have several contribution categories across different cases.

## 8. No simplistic source score

The engine must not collapse all dimensions into a single number presented as “reliability”.

A dashboard may display separate indicators for:

- timeliness;
- availability;
- verification contribution;
- independence;
- coverage contribution;
- revision activity;
- noise;
- resilience contribution.

## 9. Performance review triggers

Review is triggered by:

- repeated missed material events;
- material increase in noise;
- recurring unexplained revisions;
- loss of provenance;
- repeated endpoint failures;
- material methodology change;
- loss of unique coverage;
- discovery that apparent corroboration shares a common lineage;
- significant change in institutional role;
- persistent mismatch between source capability and assigned function.

## 10. Source improvement actions

Possible actions:

- retain unchanged;
- expand use;
- narrow function;
- move to discovery-only;
- require secondary corroboration;
- require primary corroboration;
- add monitoring;
- change endpoint;
- document limitation;
- place under review;
- suspend production use;
- deprecate.

These are editorial governance actions, not statements about the source's general trustworthiness.

## 11. Value vs authority

Authority and performance must remain separate.

A highly authoritative institution can perform poorly operationally if its feed is delayed or unavailable.

A lower-authority secondary source can perform strongly as a discovery mechanism.

Therefore:

`AUTHORITY ≠ PERFORMANCE ≠ VALUE ≠ TRUTH`

## 12. Value vs corroboration

A source can have high editorial value without being an independent corroborating lineage.

For example, a source may provide rapid discovery of an event already documented elsewhere.

Conversely, a source can add independent corroboration while providing little detection value.

## 13. Source retirement

A source should be considered for retirement when:

1. its assigned function is no longer needed;
2. a superior independent source replaces its capability;
3. operational maintenance cost is disproportionate to value;
4. its provenance becomes persistently inadequate;
5. it becomes permanently unavailable;
6. it is superseded by a better authoritative resource.

Retirement must preserve historical references to the source.

## 14. Source downgrade

Downgrade should be function-specific.

Examples:

- `PRIMARY_EVIDENCE → VERIFICATION_SUPPORT`
- `VERIFICATION_SUPPORT → DISCOVERY_ONLY`
- `PRODUCTION → MONITORING_ONLY`

A downgrade does not erase historical use.

## 15. Source upgrade

Upgrade requires documented evidence of improved capability, such as:

- verified endpoint;
- improved provenance;
- authoritative role expansion;
- independent collection capability;
- stronger methodology documentation;
- successful verification contribution.

No upgrade should be based solely on popularity.

## 16. Performance and source health

Performance observations feed source health but remain conceptually distinct.

`HEALTH` describes current operational/provenance condition.

`PERFORMANCE` describes observed effectiveness over a defined period and function.

## 17. Performance and resilience

A source with strong performance but no independent alternatives can still create resilience risk.

A source with moderate performance may be strategically valuable because it provides independent fallback capacity.

## 18. Performance and coverage

The engine must test whether an acquired source actually reduces the coverage gap for which it was introduced.

Possible result:

- `GAP_CLOSED`
- `GAP_REDUCED`
- `GAP_UNCHANGED`
- `GAP_REDEFINED`
- `FALSE_GAP`

## 19. Human editorial review

Performance data can trigger review but cannot automatically:

- label a source false;
- remove a source;
- downgrade authority globally;
- retract a publication;
- alter historical decisions.

The final decision remains human.

## 20. Core principle

> A source's editorial value is demonstrated by the function it actually performs, the evidence it contributes, and the independence or coverage capacity it adds—not by its name alone.
