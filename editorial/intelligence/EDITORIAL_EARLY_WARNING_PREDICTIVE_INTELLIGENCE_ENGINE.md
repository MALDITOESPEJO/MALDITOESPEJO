# EDITORIAL EARLY WARNING & PREDICTIVE INTELLIGENCE ENGINE

## 1. Purpose

This engine converts validated editorial signals, temporal changes, anomalies, source behavior, narrative evolution and corroborated patterns into structured **early-warning assessments**.

It is designed to identify developments that merit investigation before they become fully formed news events.

It does not turn forecasts, probabilities or model outputs into facts.

## 2. Canonical chain

`OBSERVATION → CHANGE → SIGNAL → PATTERN → EARLY-WARNING HYPOTHESIS → EVIDENCE REVIEW → HUMAN ASSESSMENT`

Predictive assessments remain hypotheses until independently confirmed.

## 3. Fundamental distinctions

- `FORECAST ≠ OBSERVATION`
- `INDICATOR ≠ EVENT`
- `RISK ≠ OCCURRENCE`
- `ANOMALY ≠ PROOF`
- `TREND ≠ DESTINATION`
- `PROBABILITY ≠ FACT`
- `MODEL OUTPUT ≠ EVIDENCE OF OCCURRENCE`
- `EARLY WARNING ≠ PUBLISHED FACT`

## 4. Warning object

An early-warning object should contain:

- warning identifier;
- underlying observations;
- signal identifiers;
- event class;
- jurisdiction;
- time window;
- baseline;
- observed deviation;
- supporting evidence;
- contradictory evidence;
- alternative explanations;
- hypothesis;
- probability or confidence where appropriate;
- expected indicators;
- invalidation conditions;
- review status;
- human reviewer.

## 5. Warning classes

- `EMERGING_EVENT`
- `ACCELERATING_TREND`
- `THRESHOLD_APPROACH`
- `THRESHOLD_CROSSING`
- `SOURCE_DEGRADATION`
- `NARRATIVE_ACCELERATION`
- `SECURITY_ESCALATION`
- `HUMANITARIAN_DETERIORATION`
- `REGULATORY_MOMENTUM`
- `MARKET_STRESS`
- `ELECTION_RISK_INDICATOR`
- `INFORMATION_INTEGRITY_ESCALATION`
- `UNKNOWN_ANOMALY`

## 6. Baseline discipline

Every anomaly should be compared against an explicit baseline where possible:

- historical range;
- seasonal pattern;
- normal publication frequency;
- geographic baseline;
- institutional baseline;
- source-specific behavior;
- methodological baseline.

A deviation from a poorly defined baseline must remain `UNCERTAIN`.

## 7. Temporal analysis

Track separately:

- `observed_at`;
- `detected_at`;
- `forecast_window_start`;
- `forecast_window_end`;
- `expected_confirmation_window`;
- `confirmed_at`.

A later-confirmed event must not be used to rewrite what was knowable at the earlier warning time.

## 8. Leading indicators

Potential indicators include:

- abnormal source activity;
- repeated threshold crossings;
- unusual geographic concentration;
- changes in institutional behavior;
- escalating narrative propagation;
- increased incident frequency;
- supply or market disruptions;
- security alerts;
- regulatory consultation or enforcement movement;
- humanitarian indicators;
- unusual information-integrity anomalies.

No individual indicator is automatically predictive.

## 9. Pattern validation

Patterns should be assessed for:

1. persistence;
2. consistency;
3. independent evidence lineages;
4. temporal coherence;
5. geographic coherence;
6. methodological stability;
7. alternative explanations;
8. historical false-positive rate;
9. current source health;
10. current integrity status.

## 10. Predictive models

If statistical, machine-learning or other predictive models are used, preserve:

- model/version;
- input dataset/version;
- extraction time;
- feature definitions;
- forecast horizon;
- output probability/range;
- known limitations;
- calibration information where available;
- model drift status.

Model output must remain distinguishable from observed evidence.

## 11. Early-warning confidence

Use a separate confidence state:

`LOW`, `MODERATE`, `HIGH`, `VERY_HIGH`, `UNKNOWN`.

Confidence reflects support for the warning hypothesis, not certainty that the predicted event will occur.

## 12. Invalidation conditions

Every material warning should specify what would weaken or invalidate it, such as:

- indicator reversal;
- source correction;
- methodology change;
- contradictory primary evidence;
- alternative causal explanation becoming better supported;
- forecast window expiration;
- expected event not materializing.

Expired warnings must not remain active indefinitely.

## 13. False-positive governance

The system must preserve false alarms and missed warnings for calibration.

Track:

- warning issued;
- event confirmed;
- event not confirmed;
- timing error;
- scope error;
- geographic error;
- severity error;
- evidence error;
- source failure.

Performance review must not become a simplistic score of editorial quality.

## 14. Alert levels

- `WATCH` — weak or preliminary indicator;
- `ADVISORY` — meaningful pattern requiring editorial monitoring;
- `HIGH` — convergent indicators with material potential consequence;
- `CRITICAL` — strong evidence of imminent or rapidly developing consequential event.

Alert level is not equivalent to probability or truth.

## 15. Hard blocks

Do not escalate a warning solely because:

- a story is viral;
- a single source is sensational;
- a model assigns high probability without reliable inputs;
- an anomalous observation has no baseline;
- multiple outlets share one upstream source;
- a politically attractive hypothesis fits the pattern;
- historical hindsight makes the warning appear obvious.

## 16. Transition to confirmed event

The transition:

`WARNING → EVENT`

requires new evidence establishing that the event actually occurred.

The existence of a warning must never be cited as evidence that the event occurred.

## 17. Human editorial gate

No automated warning may:

- publish itself;
- accuse an actor;
- declare an event occurred;
- characterize a forecast as fact;
- assign malicious intent;
- trigger correction/retraction without human review.

## 18. Integration

`SOURCE HEALTH → OBSERVATION → SIGNAL → LINEAGE → INFORMATION FLOW → NARRATIVE/ACTOR ANALYSIS → EARLY WARNING → EVIDENCE REVIEW → CASE → HUMAN DECISION`

## 19. Core principle

> **MALDITOESPEJO must be capable of seeing a story coming without pretending that it has already happened.**
